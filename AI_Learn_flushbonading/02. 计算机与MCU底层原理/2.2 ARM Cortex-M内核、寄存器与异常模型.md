## 二、内核寄存器与普通函数调用

### 内核寄存器与调试速查

| 寄存器 | 调试时怎么看 |
|---|---|
| `R0–R12` | 保存参与运算的数值、地址和中间结果。按 AAPCS32，前几个 32 位整数参数通常依次用 `R0–R3`，单个 `uint32_t` 返回值放在 `R0` |
| `SP（R13）` | 指向当前使用的栈顶。先确认此刻选中 `MSP` 还是 `PSP`，再到该地址对应的内存查看压栈数据 |
| `LR（R14）` | 链接寄存器。`BL` 将普通函数的返回信息写入 `LR`，异常入口将 `EXC_RETURN` 写入 `LR`。读到值时，结合当前指令和执行阶段解释它 |
| `PC（R15）` | 程序计数器。可结合反汇编定位正在执行的代码。进入异常后，另从异常栈帧读取被打断代码保存的 `PC` |
| `xPSR` | 程序状态。`APSR` 部分包含运算条件标志，`IPSR` 部分记录当前异常编号（0 表示 Thread 模式），`EPSR` 部分包含 Thumb 等执行状态 |

### 为什么调用其他函数之前常保存 LR

例如 `main()` 用 `BL` 调用 `read_sensor()`，`read_sensor()` 再用 `BL` 调用 `spi_transfer()`。第一次 `BL` 写入返回 `main()` 的位置，第二次 `BL` 用返回 `read_sensor()` 的位置覆盖同一个 `LR`。如果 `read_sensor()` 后续还要返回 `main()`，需要在第二次调用前保留原来的链接信息。常见做法是 `PUSH {R4, LR}`，函数退出时用 `POP {R4, PC}` 恢复 `R4`，同时把保存的返回信息装进 `PC`。

下面是教学用 Thumb 汇编，假设调用者已经令 `R4` 指向 SRAM 中的 `output`，初值为 0。

```asm
    MOVS R0, #9
    BL   prepare
    STR  R0, [R4]
    B    caller_continue

prepare:
    PUSH {R4, LR}
    BL   add_offset
    POP  {R4, PC}

add_offset:
    ADDS R0, R0, #3
    BX   LR

caller_continue:
    NOP                 @ 代表调用者后续代码
```

外层的 `BL prepare` 把调用者中 `STR` 的返回信息写进 `LR`。`prepare` 先把它保存到栈里，因为下一条 `BL add_offset` 会覆盖 `LR`，使它对应 `POP` 的位置。`add_offset` 用 `BX LR` 回到 `POP`，随后 `POP {R4, PC}` 把外层的返回信息装进 `PC`，回到调用者。此刻 `R0 = 12`，执行 `STR` 后 `output` 才从 0 变成 12。

## 三、异常进入、现场保存与返回

### Thread、Handler 与栈的选择

| 执行上下文 | 模式 | 当前栈指针 |
|---|---|---|
| 复位后运行普通代码，沿用默认设置 | Thread | MSP |
| 任务或普通代码，`CONTROL.SPSEL = 1` | Thread | PSP |
| USART ISR、HardFault 等异常处理程序 | Handler | MSP |

`MSP`、`PSP` 是两个各存一个地址的内核寄存器，实际栈数据写入它们指向的 SRAM。异常进入时，硬件在**被打断代码原来使用的栈**上写异常栈帧。进入 Handler 后，ISR 执行访栈指令使用 `MSP`。若用 PSP 的任务 A 被 USART ISR 打断，随后 USART ISR 又被定时器抢占，第一份现场在任务 A 的 PSP 栈，第二份现场在 MSP 栈。

FreeRTOS 的 Cortex-M4F 移植给每个任务分配独立栈。切换任务时，硬件基本现场留在任务栈中，`PendSV` 再保存软件负责的寄存器，并把栈顶地址记录到该任务的 TCB。切回时从 TCB 找回相应任务栈。

### 从 IRQ 号定位 ISR 入口

`SCB->VTOR` 给出当前向量表基址。每项 4 字节，第 0 项是初始 MSP，第 1 项是复位入口，外部 IRQ 从第 16 项开始。

`向量表项地址 = VTOR + (16 + 外部 IRQ 号) × 4`

例如 `VTOR = 0x08004000`，STM32F407 的 USART2 外部 IRQ 号为 38，则表项在 `0x080040D8`。若读到的向量值是 `0x08005101`，最低位标识 Thumb 状态，ISR 的取指地址是 `0x08005100`。

### 栈帧与 PUSH 分开计算

以没有浮点扩展和额外对齐填充的基本异常栈帧为例，8 个 32 位值共 32 字节。以下偏移以**异常硬件入栈完成后**的栈指针为基准。 偏移从低地址到高地址排列，起点对应 `R0`。

| 相对入栈后栈指针的字节偏移 | 保存的 32 位值 |
|---|---|
| `+0x00` | 被打断代码的 `R0` |
| `+0x04` | `R1` |
| `+0x08` | `R2` |
| `+0x0C` | `R3` |
| `+0x10` | `R12` |
| `+0x14` | 被打断代码原来的 `LR` |
| `+0x18` | 异常返回时恢复到 `PC` 的值 |
| `+0x1C` | 被打断代码原来的 `xPSR` |

查已保存的硬件现场时，用**入栈后的栈指针加表中偏移**。执行 ISR 中的 `PUSH {LR}` 时，用**执行指令前的 MSP 减 4**。如果需要从硬件入栈前的栈顶回推，基本帧的 `xPSR`、`PC`、旧 `LR` 分别位于 `−0x04`、`−0x08`、`−0x0C`，这个换算以没有额外对齐填充为前提。

例如任务使用 `PSP = 0x20005000`，进中断后 `PSP = 0x20004FE0`，任务旧 LR 存在 `0x20004FF4`，压栈的 PC 存在 `0x20004FF8`。如果 ISR 执行第一条指令前 `MSP = 0x20007000`，执行 `PUSH {LR}` 时用的是当前 MSP，减去一个寄存器占的 4 字节，把**此刻 LR 里的值**写到 `0x20006FFC`。对齐设置和浮点上下文可增加硬件占用空间，普通函数的栈帧则由编译器按需安排。

### EXC_RETURN 怎样让 CPU 恢复执行

ISR 刚进入时，硬件给 `LR` 写入 `EXC_RETURN`。如果 ISR 用 `BL` 调其他函数，应先保存这个值。正常结束时可恢复它并执行 `BX LR`，由硬件按编码选择返回模式和栈。执行位置从该栈帧中保存的 `PC` 恢复。

| 基本栈帧的 EXC_RETURN | 返回模式 | 恢复用的栈 |
|---|---|---|
| `0xFFFFFFF1` | Handler | MSP |
| `0xFFFFFFF9` | Thread | MSP |
| `0xFFFFFFFD` | Thread | PSP |

## 四、NVIC 优先级、抢占与屏蔽

STM32F407 的外部 IRQ 优先级字段用高 4 位。分组决定有几位用于抢占、几位用于子优先级。优先级数值越小，响应优先级越高。正在执行的 IRQ 是 Active，等待响应的 IRQ 可以是 Pending。

- 抢占看抢占优先级。两个 IRQ 抢占优先级相同，后到的 IRQ 先挂起。
- 多个 IRQ 都挂起且都能得到响应时，先比较抢占优先级，再比较子优先级，两者都相同则 IRQ 编号较小者先响应。
- `PRIMASK = 1` 阻止可配置优先级的异常进入，NMI、HardFault 仍可进入。`BASEPRI` 非零时屏蔽与门槛同级或更低的可配置异常，`BASEPRI = 0` 取消这一级屏蔽。

```c
/* STM32CubeF4 HAL，示例采用 4 位抢占优先级、0 位子优先级。 */
HAL_NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_4);
HAL_NVIC_SetPriority(TIM2_IRQn, 2u, 0u);
HAL_NVIC_SetPriority(USART2_IRQn, 6u, 0u);
```

两个 IRQ 均已使能且无屏蔽时，TIM2 可抢占 USART2。这个分组下，若 `BASEPRI = 0x50`，则逻辑优先级 0–4 可通过这道门槛，5–15 被屏蔽。HAL 设置抢占优先级时传逻辑值，直接写 BASEPRI 时用编码值 `5u << 4`。

## 五、工程实战：在调试器定位 HardFault

### 现场定位要看的寄存器

| 寄存器 | 定位时看什么 |
|---|---|
| 入口 `LR` | 在 `HardFault_Handler` 的第一条指令读 `EXC_RETURN`。它帮助判断异常前的模式和存放栈帧的栈。基本帧中 `0xFFFFFFF1` 对应 Handler/MSP，`0xFFFFFFF9` 对应 Thread/MSP，`0xFFFFFFFD` 对应 Thread/PSP |
| `MSP` / `PSP` | 用 `EXC_RETURN` 选出存放硬件现场的栈。例程若已经执行软件压栈，需要按实际指令恢复到异常栈帧起点再读 |
| 栈帧中的 `PC` / `LR` / `xPSR` | `PC` 用于对照反汇编，旧 `LR` 可辅助追踪调用链，`xPSR` 可辅助判断故障前的模式和执行状态 |
| `SCB->HFSR` | HardFault 状态。`FORCED` 表示可配置故障升级，继续查 CFSR。`VECTTBL` 表示异常进入时读取向量表遇到总线错误，可检查 VTOR 和向量表所在内存 |
| `SCB->CFSR` | 可配置故障状态。位 `[7:0]` 为 MemManage，`[15:8]` 为 BusFault，`[31:16]` 为 UsageFault。一次读取可能同时看到多个标志 |
| `SCB->BFAR` | 总线故障访问地址。检查 `CFSR.BFARVALID` 置位后再使用 |
| `SCB->MMFAR` | 内存管理故障地址。检查 `CFSR.MMARVALID` 置位后再使用 |
| `SCB->SHCSR` | 辅助核对 MemManage、BusFault、UsageFault 的处理程序是否已使能。三者使能位依次为位 16、17、18。`FORCED` 也可能由当时的异常优先级导致 |

### 常用状态位速查

下表位号按 **32 位 HFSR 或 CFSR 的整体编号**列出。手册若单独画出 8 位 BFSR，BFSR 的位 7 对应整个 CFSR 的位 15。

| 标志 | 位号 | 掩码 | 怎么用 |
|---|---:|---|---|
| `HFSR.FORCED` | 30 | `0x40000000` | 确认有故障升级，读 CFSR 找原因 |
| `HFSR.VECTTBL` | 1 | `0x00000002` | 排查向量表读取 |
| `CFSR.BFARVALID` | 15 | `0x00008000` | 判定 BFAR 是否给出有效地址 |
| `CFSR.STKERR` | 12 | `0x00001000` | 异常入栈发生总线错误，先核查栈帧是否可靠 |
| `CFSR.IMPRECISERR` | 10 | `0x00000400` | 非精确数据总线错误，压栈的 PC 只作排查线索 |
| `CFSR.PRECISERR` | 9 | `0x00000200` | 精确数据总线错误，可用压栈的 PC 定位出错指令 |
| `CFSR.MMARVALID` | 7 | `0x00000080` | 判定 MMFAR 是否给出有效地址 |
| `CFSR.MSTKERR` | 4 | `0x00000010` | 异常入栈发生内存管理故障，先核查栈帧是否可靠 |

代码里可以通过 CMSIS 提供的命名掩码检查每一位。以 BFAR 有效位为例：

```c
#include <stdbool.h>
#include "stm32f4xx.h"

static bool bus_fault_address_valid(uint32_t cfsr)
{
    return (cfsr & SCB_CFSR_BFARVALID_Msk) != 0u;
}
```

### 用一份现场走完定位过程

调试器停在 `HardFault_Handler` 的第一条指令。假设基本栈帧保存成功，入口 `LR = 0xFFFFFFFD`，`PSP = 0x20001FE0`。

1. 用入口 LR 确定栈帧在 PSP 对应的栈。保存 PC 的内存槽位于 `0x20001FE0 + 0x18 = 0x20001FF8`。假设槽内读到 `0x080034B2`，这是保存下来的代码地址。
2. 若 `HFSR = 0x40000000`，则 `FORCED = 1`。若 `CFSR = 0x00008200`，按掩码分别得到 `PRECISERR = 1` 和 `BFARVALID = 1`。假设 `BFAR = 0x60000020`，这是有效的故障访问地址。
3. 用本次固件构建的 ELF 或反汇编查 `0x080034B2` 处的指令，再追踪那条指令为什么访问 `0x60000020`。如果另一份现场的 `CFSR = 0x00000400`，则是非精确数据总线错误，保存的 PC 只提供报告故障时的执行线索，BFAR 也没有有效地址。

## 六、个人易错点与复盘

| 本轮易错点 | 下次独立复核时怎么判断 |
|---|---|
| 把普通 `BL` 后的 LR 当成 `EXC_RETURN` | 先看是谁更新 LR。`BL` 写入调用点后的位置，异常入口写入返回编码 |
| 用 `VTOR + IRQn` 查向量表 | 先加 16 得表下标，再乘 4 转为字节偏移 |
| 算 ISR 的 `PUSH {LR}` 时套用 32 字节硬件栈帧 | 先确认动作是硬件入栈还是软件指令。软件压一个 32 位值，从当时的 SP 减 4。本轮已讲解，待独立复核 |
| 把压栈的 PC 当成出错寄存器，把 BFAR 当作最后一次访问 | 看精确性和有效位。PC 用来查指令，BFAR 有效时用来查故障访问地址 |

## 七、复习自检

1. 假设任务在 PSP 上运行，`PSP = 0x20006000`，硬件只保存基本栈帧。入栈后 PSP 是多少？保存 PC 的地址呢？进入 ISR 后，若执行前 `MSP = 0x20008000`，一条 `PUSH {LR}` 向哪里写、写什么？
2. `VTOR = 0x08008000`，外部 IRQ 号为 39。表项地址是多少？该表项提供什么信息？
3. USART 和 TIM 的抢占优先级相同，TIM 的子优先级更高。USART 已执行时 TIM 能抢占吗？两者均挂起且都可响应时，谁先执行？
4. `CFSR.IMPRECISERR = 1`、`CFSR.BFARVALID = 0` 时，压栈的 PC 和 BFAR 各能提供什么线索？

**参考答案**

1. `PSP = 0x20005FE0`。压栈 PC 存在 `0x20005FF8`。`PUSH {LR}` 把 `0xFFFFFFFD` 写到 `0x20007FFC`。
2. `0x08008000 + (16 + 39) × 4 = 0x080080DC`。取出的向量值用于进入 ISR。
3. 不能抢占。两者都能响应时，TIM 先执行。
4. PC 可帮助缩小排查范围，不能直接定位故障指令。BFAR 当前值不能作为有效故障访问地址。

## 八、本节总结与参考资料

普通函数靠调用约定和保存的返回信息完成调用。异常进入由硬件读取向量并保存基本现场，异常退出由 EXC_RETURN 指定恢复方式。排查故障时，把**栈帧所在地址、栈帧保存的代码地址和故障访问地址**分别核实。
