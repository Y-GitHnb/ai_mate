## 一、必备知识框架

调试中断时，依次确认外设有没有发生事件、外设是否发出中断请求、NVIC 是否允许响应，以及 CPU 当前能否接纳该请求。CPU 接纳 IRQ 后，从向量表读取处理函数入口，保存被打断的现场并进入 ISR。向量表和异常帧的细节见 2.2、2.4。

| 环节 | 以 TIM2 更新中断为例 | 调试时读什么 |
|---|---|---|
| 外设记录事件 | 更新事件置位 `UIF` | `TIM2->SR` |
| 外设允许发请求 | `UIE=1` 时，置位的 `UIF` 可产生请求 | `TIM2->DIER` |
| NVIC 记录和使能 IRQ | Pending 表示等待处理，Enable 决定该外部 IRQ 是否获准响应 | `NVIC_GetPendingIRQ()`、`NVIC_GetEnableIRQ()` |
| CPU 响应请求 | 考虑屏蔽、当前执行优先级及其他待处理 IRQ | `PRIMASK`、`BASEPRI`、优先级配置 |

### Pending、Active 与 Enable

`NVIC_EnableIRQ(IRQn)` 操作使能位。外设请求可以让一个尚未使能的 IRQ 进入 Pending。IRQ 使能后，已有的 Pending 可以在优先级与屏蔽条件允许时立即得到响应。软件需要主动置 Pending 时，可调用 `NVIC_SetPendingIRQ(IRQn)`。

CPU 接纳这条 IRQ 后，撤掉本次响应对应的 Pending，并将它标为 Active。它被更高优先级 ISR 打断时仍是 Active，直至完成异常返回。同一 IRQ 在 Active 期间可有后续请求待处理。对持续有效的电平请求，异常返回时仍有效就可以让它再次挂起。`NVIC_GetActive()` 可查看指定外部 IRQ 是否 Active。`SCB->ICSR` 的 `VECTACTIVE` 给出 CPU 当前执行的异常号。

## 二、优先级编码、抢占与嵌套

STM32F407 实现 4 个优先级位，放在 8 位优先级字段的高 4 位。逻辑数值越小，优先级越高。分组决定 4 位中多少给抢占优先级、多少给子优先级。组内比较子优先级时，数值同样越小越先服务。

| 比较场景 | 规则 |
|---|---|
| 新 IRQ 试图打断正在执行的 ISR | 新 IRQ 的抢占优先级必须更高 |
| 多个符合响应条件的 IRQ 同时 Pending | 先比抢占优先级，再比子优先级 |
| 两个待处理 IRQ 的编码优先级完全相同 | 异常号较小的先服务 |

例如配置 2 位抢占优先级、2 位子优先级，设置 USART2 为 `(2, 1)`，TIM2 为 `(2, 0)`，DMA 为 `(1, 0)`。USART2 执行期间 TIM2 只能等待，随后到达的 DMA 可以抢占 USART2。DMA 退出时，仍处于 Active 的 USART2 先继续执行。USART2 结束后轮到 TIM2。若 TIM2 是此时唯一符合条件的 Pending，CPU 可以通过尾链从 USART2 转入 TIM2，省去一次恢复和重新保存现场，最后才回到线程代码。

使用 CMSIS 时，先按项目已配置的分组编码，再设置逻辑优先级。假设此时项目分组为 2 位抢占加 2 位子优先级，USART2 的逻辑值 `(2 << 2) | 1` 为 9，硬件优先级字段为 `0x90`。CMSIS 的 `NVIC_SetPriority()` 会完成左移。

```c
uint32_t group = NVIC_GetPriorityGrouping();
uint32_t priority = NVIC_EncodePriority(group, 2U, 1U);
NVIC_SetPriority(USART2_IRQn, priority);
```

## 三、屏蔽寄存器与临界区

| 寄存器 | Cortex-M4 上的作用 |
|---|---|
| `PRIMASK` | 写 1 屏蔽所有可配置优先级的异常。NMI 和 HardFault 仍能响应。 |
| `BASEPRI` | 设为非零值后，对同等或更低优先级的异常施加门槛。写 0 解除这道门槛。 |

采用 4 位抢占优先级、0 位子优先级，且无其他屏蔽时，`BASEPRI=0x50` 对应逻辑优先级 5。逻辑优先级 3 可以通过，5 和 7 会被挡住。CMSIS 的 `__set_BASEPRI()` 接收寄存器编码，例如 `5U << (8U - __NVIC_PRIO_BITS)`。读到 Pending 时，还需要检查当前屏蔽与执行优先级。

NMI 是 Non-Maskable Interrupt，即不可屏蔽中断。它是 Cortex-M4 的系统异常，固定优先级为 −2，仅低于 Reset。STM32F407 的一个实际来源是已启用的时钟安全系统 CSS 检测到 HSE 故障，进入 `NMI_Handler()` 后可检查 `RCC_CIR` 中的 CSS 故障标志。

裸机特权代码可以保存并恢复进入前的 `PRIMASK`，从而正确支持嵌套。若外层已经设为 1，内层退出时也恢复为 1。内层直接调用 `__enable_irq()` 会提前清掉外层的屏蔽。

```c
uint32_t saved_primask = __get_PRIMASK();
__disable_irq();
/* 执行短小的临界区操作。 */
__set_PRIMASK(saved_primask);
```

临界区的保护范围由实际被屏蔽的执行路径决定。DMA 与其他总线主设备可以继续工作，NMI 也仍能进入。使用 RTOS 时应遵循该系统的临界区接口和优先级约束。

## 四、工程实例 · TIM2 中断刚使能就进，退出后又进

初始化时，计数溢出或符合配置条件的软件更新都可留下 `UIF=1`。如果这个标志属于不打算交给 ISR 处理的初始化事件，应在中断通路打开前按手册清掉它。初始化时需要丢弃旧请求的情况下，可以先处理外设源，再清已有的 NVIC Pending，最后使能所需的中断通路。

运行中若每次退出又立即进入，先看 ISR 是否清除了实际挂起的外设源。假设只使用 TIM2 更新中断，且 HAL 的 `htim2` 已正确初始化，可按以下方式检查和应答更新源。

```c
void TIM2_IRQHandler(void)
{
    if (((TIM2->SR & TIM_SR_UIF) != 0U) &&
        ((TIM2->DIER & TIM_DIER_UIE) != 0U)) {
        __HAL_TIM_CLEAR_IT(&htim2, TIM_IT_UPDATE);
        handle_tick();
    }
}
```

`UIF` 在 `TIM2->SR` 中是 `rc_w0`，对目标位写 0 清除。EXTI 的 `PR` 对目标位写 1 清除。选择写法时先查寄存器定义。

| 观察到的时序 | 原因 |
|---|---|
| 只发生一次更新，ISR 只清 NVIC Pending，`UIF` 始终为 1 | 旧外设请求仍有效，返回时可再次挂起 |
| ISR 成功清 `UIF`，执行过程中又有更新，`UIF` 再变成 1 | 新事件待服务，同一个 IRQ 等当前实例退出后才有机会再次进入 |

`UIF` 只有一位。多次更新若都发生在清标志之前，可能表现为同一个置位状态。统计每次更新时需根据外设时序和最坏 ISR 延迟判断是否会合并。

## 五、必须掌握的知识重点

- 能从事件、外设使能、NVIC Enable、Pending、Active、CPU 屏蔽这几处推导 ISR 是否进入。
- 能从分组与逻辑优先级推导抢占、等待顺序和寄存器编码。
- 能解释 `BASEPRI` 的阈值包含同级、`PRIMASK` 的边界，以及嵌套临界区恢复原值的原因。
- 能靠外设状态和代码执行顺序定位持续旧请求与真正的新事件。

## 六、个人易错点与复盘

- 综合验收正确推导 USART2 被 DMA 抢占时的 Active 和 Pending，并正确按子优先级排 EXTI0 与 TIM2。
- 正确判断了优先级 3 可以通过 `BASEPRI=0x50`、优先级 5 被屏蔽，独立写出保存和恢复 `PRIMASK` 的 CMSIS 调用。
- 正确判断 TIM2 IRQ 使能后可以响应旧请求。复习时用一个没有既有请求的反例核对 Enable 和 Pending 两个独立状态，同时短查 NMI 进入条件。
- `TIM2->SR.UIF` 是位的描述。在 CMSIS 的 C 代码中通过 `TIM_SR_UIF` 掩码读取，通过符合 `rc_w0` 语义的写法或 HAL 宏清除。

## 七、复习自检

1. TIM2 的更新请求已经挂起，NVIC 通道关闭。开通道前后分别读取 Enable 与 Pending，解释为什么开通道后有时直接进入 ISR。
2. 四位均用于抢占，`BASEPRI=0x60`。逻辑优先级 5、6 中谁能得到响应？再置 `PRIMASK=1` 时结果如何？NMI 呢？
3. 在 `handle_tick()` 开始前以及退出前分别读 `UIF`。在清除成功且退出前再次读到 1 的前提下，解释事件来源及为什么同一个 TIM2 IRQ 要等当前 ISR 完成。

## 八、本节总结与官方资料

CPU 根据使能、等待状态、优先级和屏蔽条件接纳 IRQ。进入 ISR 后，由对应外设的寄存器规则应答事件。临界区退出时恢复进入前的屏蔽状态。
