## 一、核心概念
### 1.1 指针的本质
指针是用于保存地址信息的变量，通过指针可以间接访问其指向的对象。

```c
#include <stdint.h>

uint32_t a = 100;
uint32_t *p = &a;
```

其中：

+ `a`：普通变量，保存数值 100。
+ `&a`：获取变量 a 的地址。
+ `p`：指针变量，保存 a 的地址。
+ `*p`：解引用指针，访问 a。
+ `&p`：获取指针变量 p 自身的地址。

假设 a 位于 `0x20000000`，p 位于 `0x20000010`：

| 表达式 | 结果 |
| --- | --- |
| `a` | 100 |
| `&a` | 0x20000000 |
| `p` | 0x20000000 |
| `*p` | 100 |
| `&p` | 0x20000010 |


这些地址仅用于示意，实际位置由编译器、链接器和运行环境决定。

**核心结论：指针本身也是变量。修改指针保存的地址，与修改指针所指对象的值，是两种不同的操作。**

### 1.2 取地址与解引用
```c
uint32_t a = 100;
uint32_t b = 200;

uint32_t *p = &a;

*p = 300;  // 修改 a，a = 300
p = &b;    // 修改 p 的指向
*p = 400;  // 修改 b，b = 400
```

最终：

```latex
a = 300
b = 400
p 指向 b
```

注意 `*` 有两种使用场景：

```c
uint32_t *p;  // 声明一个指针

*p = 100;     // 解引用指针
```

## 二、指针类型与指针运算
### 2.1 指针本身的大小
在常见的 32 位 STM32、ESP32-S3 开发环境中：

| 类型 | 通常占用字节数 |
| --- | ---: |
| uint8_t | 1 |
| uint16_t | 2 |
| uint32_t | 4 |
| uint64_t | 8 |
| uint8_t * | 4 |
| uint16_t * | 4 |
| uint32_t * | 4 |


需要区分：

+ `sizeof(p)`：指针变量自身的大小。
+ `sizeof(*p)`：指针所指对象类型的大小。

例如：

```c
uint16_t a = 100;
uint16_t *p = &a;

sizeof(p);   // 常见 32 位 MCU 上为 4
sizeof(*p);  // 2
```

指针大小由平台实现决定，并不是所有 MCU 都使用 4 字节指针。

### 2.2 指针运算的原理
指针运算以所指元素为单位，而不是直接以字节为单位。

对于一个有效的数组元素指针：

**地址移动字节数 = 移动元素个数 × sizeof(元素类型)**

例如：

```c
uint16_t buf[5] = {
    10, 20, 30, 40, 50
};

uint16_t *p = buf;

p = p + 2;
```

假设 buf 起始地址为 `0x20000000`：

```latex
buf[0]：0x20000000
buf[1]：0x20000002
buf[2]：0x20000004
buf[3]：0x20000006
buf[4]：0x20000008
```

执行 `p + 2` 后：

```latex
p = 0x20000004
*p = 30
```

注意十六进制计算：

```latex
0x0A = 十进制 10
0x10 = 十进制 16
0x12 = 十进制 18
```

### 2.3 指针运算的边界
在 C 语言中，指针加减操作不能任意跨越内存对象。

```c
uint8_t buf[5] = {0};

uint8_t *p = buf;

p + 4; // 合法：指向最后一个元素
p + 5; // 合法：数组尾后指针
```

但不能解引用数组尾后指针：

```c
// *(p + 5) = 10;  // 未定义行为
```

超出允许范围的指针运算本身也可能属于未定义行为，不是只有真正解引用时才出问题。

同一个数组中，两个有效元素指针可以进行指针差值运算：

```c
uint8_t *p1 = &buf[1];
uint8_t *p2 = &buf[4];

ptrdiff_t diff = p2 - p1; // 3
```

这里差值表示相隔的元素数量，而不是字节数。`ptrdiff_t` 定义在 `<stddef.h>` 中。

## 三、指针与数组
### 3.1 数组名不是指针变量
```c
uint16_t buf[5] = {
    10, 20, 30, 40, 50
};

uint16_t *p = buf;
```

`buf` 是数组对象，而 `p` 是指针变量。

两者的区别：

| 项目 | 数组 buf | 指针 p |
| --- | --- | --- |
| 类型 | uint16_t[5] | uint16_t * |
| 代表对象 | 完整数组 | 指针变量 |
| sizeof | 10 | 常见 32 位平台为 4 |
| 能否重新赋地址 | 不可以 | 可以 |
| 能否使用下标 | 可以 | 可以（范围必须有效） |


例如：

```c
p = p + 1;       // 合法

// buf = buf + 1; // 不合法
```

**数组表达式在大多数使用场景下会转换为指向第一个元素的指针，但数组本身并不是指针变量。**

### 3.2 buf、&buf[0] 和 &buf
```c
uint16_t buf[5] = {0};
```

| 表达式 | 类型 | 含义 |
| --- | --- | --- |
| buf | uint16_t[5] | 数组表达式，通常转换为首元素指针 |
| &buf[0] | uint16_t * | 第一个元素的地址 |
| &buf | uint16_t (*)[5] | 整个数组的地址 |


例如：

```c
uint16_t *p = buf;
uint16_t (*q)[5] = &buf;
```

在常见 MCU 平台上，p 和 q 对应的起始内存位置相同。

但是：

```c
sizeof(*p);  // 2
sizeof(*q);  // 10
```

因此：

```c
p + 1; // 地址前进 2 字节
q + 1; // 地址前进 10 字节
```

`q + 1` 指向整个数组对象之后，不能解引用。

### 3.3 数组指针与指针数组
这两个概念很容易混淆。

**数组指针：**

```c
uint16_t (*p)[5];
```

表示 p 是一个指针，指向包含 5 个 uint16_t 元素的数组。

访问元素：

```c
uint16_t buf[5] = {10, 20, 30, 40, 50};

uint16_t (*p)[5] = &buf;

uint16_t value = (*p)[2]; // 30
```

**指针数组：**

```c
uint16_t *p[5];
```

表示 p 是一个包含 5 个元素的数组，每个元素都是 uint16_t 指针。

示例：

```c
uint16_t a = 10;
uint16_t b = 20;

uint16_t *ptr_array[2] = {&a, &b};
```

访问：

```c
*ptr_array[0]; // 10
*ptr_array[1]; // 20
```

记忆方法：

+ `uint16_t (*p)[5]`：p 首先是指针。
+ `uint16_t *p[5]`：p 首先是数组。

### 3.4 数组下标和指针运算
对于有效的数组元素访问：

```c
buf[i]
```

等价于：

```c
*(buf + i)
```

例如：

```c
uint8_t data[3] = {10, 20, 30};

data[1];       // 20
*(data + 1);   // 20
```

数组下标在底层语言规则中与指针运算密切相关，但不代表数组对象和指针变量是同一种东西。

## 四、sizeof 与数组传参
### 4.1 sizeof 数组与 sizeof 指针
```c
uint32_t buf[10];
uint32_t *p = buf;
```

在常见的 32 位 MCU 环境下：

```c
sizeof(buf);     // 40
sizeof(p);       // 4
sizeof(buf[0]);  // 4
```

对于非变长数组，通常使用下面的方式计算元素数量：

```c
size_t count =
    sizeof(buf) / sizeof(buf[0]);
```

注意：这个写法必须在 `buf` 仍然是实际数组表达式的上下文中使用，不能直接拿普通指针变量代替。

### 4.2 数组作为函数参数
例如：

```c
void process(uint32_t data[10])
{
    size_t size = sizeof(data);
}
```

在函数参数声明中：

```c
uint32_t data[10]
```

会被调整为：

```c
uint32_t *data
```

因此在常见 32 位 MCU 上：

```c
sizeof(data); // 4，而不是 40
```

**函数形参写成数组形式，不表示函数自动获得数组长度信息。**

### 4.3 正确的驱动接口设计
建议使用“数据指针 + 长度”的形式：

```c
#include <stdint.h>
#include <stddef.h>

void process_samples(const uint16_t *data,
                     size_t count)
{
    if (data == NULL) {
        return;
    }

    for (size_t i = 0; i < count; i++) {
        uint16_t sample = data[i];

        // 在这里处理 sample
        (void)sample;
    }
}
```

调用：

```c
uint16_t adc_buf[5] = {
    1000, 1200, 1300, 1400, 1500
};

size_t count =
    sizeof(adc_buf) / sizeof(adc_buf[0]);

process_samples(adc_buf, count);
```

工程注意事项：

1. `data` 指向数据缓冲区。
2. `count` 表示元素个数。
3. 调用者需要保证至少有 count 个有效元素。
4. 函数不能仅凭指针判断真实缓冲区容量。
5. 长度参数必须明确是字节数还是元素数量。

## 五、二级指针
### 5.1 二级指针的定义
一级指针保存普通对象的地址。

二级指针保存一级指针对象的地址。

```c
uint32_t a = 100;

uint32_t *p = &a;

uint32_t **pp = &p;
```

关系：

```latex
pp → p → a
```

| 表达式 | 含义 |
| --- | --- |
| p | a 的地址 |
| *p | a 的值 |
| pp | p 的地址 |
| *pp | p |
| **pp | a 的值 |


例如：

```c
**pp = 200;  // 修改 a

uint32_t b = 300;

*pp = &b;    // 修改 p，让 p 指向 b

**pp = 400;  // 修改 b
```

最终：

```latex
a = 200
b = 400
p 指向 b
pp 仍然指向 p
```

### 5.2 C 语言的函数参数采用值传递
```c
void change_ptr(uint8_t *p)
{
    static uint8_t b = 20;
    p = &b;
}
```

调用：

```c
uint8_t a = 10;
uint8_t *data = &a;

change_ptr(data);
```

函数执行结束后，`data` 仍然指向 a。

原因：

+ 调用函数时，形参 p 得到 data 保存的地址值副本。
+ p 和 data 是两个独立的指针变量。
+ 修改形参 p，不会直接改变调用者的 data。
+ 函数返回后，形参 p 的生命周期结束。
+ data 并不存在“重新恢复指向”的过程，它始终没有被修改。

**核心结论：函数形参是独立变量，函数返回不会自动撤销通过指针完成的外部数据修改。**

### 5.3 通过一级指针修改外部数据
```c
void change_value(uint8_t *p)
{
    *p = 100;
}

int main(void)
{
    uint8_t a = 10;

    change_value(&a);

    // a = 100

    return 0;
}
```

虽然传入的是地址值副本，但函数通过指针访问的是调用者的原始对象。

所以函数可以修改 a。

### 5.4 通过二级指针修改外部指针
```c
static uint8_t buf[3] = {10, 20, 30};

void get_buffer(uint8_t **out)
{
    if (out == NULL) {
        return;
    }

    *out = buf;
}
```

调用：

```c
uint8_t *data = NULL;

get_buffer(&data);
```

函数内部：

```c
*out = buf;
```

等价于修改调用者的：

```c
data = buf;
```

因此 data 最终指向 buf。

### 5.5 什么时候需要二级指针？
| 需求 | 推荐参数形式 |
| --- | --- |
| 读取调用者的数据 | const uint8_t * |
| 修改调用者数组的元素 | uint8_t * |
| 修改调用者的普通整数变量 | uint32_t * |
| 修改调用者的一级指针变量 | uint8_t ** |
| 返回只读缓冲区指针 | const uint8_t ** |


判断原则：

**不是处理数组就需要二级指针，而是当函数需要修改调用者的指针变量本身时，通常才需要传入该指针变量的地址。**

## 六、const 与指针
### 6.1 三种常见声明
```c
const uint8_t *p1;

uint8_t *const p2 = &a;

const uint8_t *const p3 = &a;
```

| 声明 | 能修改指针指向 | 能通过该指针修改数据 |
| --- | --- | --- |
| const uint8_t *p | 可以 | 不可以 |
| uint8_t *const p | 不可以 | 可以 |
| const uint8_t *const p | 不可以 | 不可以 |


### 6.2 指向 const 的指针
```c
uint8_t a = 10;
uint8_t b = 20;

const uint8_t *p = &a;

p = &b;     // 合法
// *p = 30; // 不合法
```

这里 const 约束的是通过 p 对所指对象的修改。

它不表示 a 本身变成了不可修改对象。

```c
a = 50; // 合法
```

### 6.3 常量指针
```c
uint8_t a = 10;
uint8_t b = 20;

uint8_t *const p = &a;

*p = 30;   // 合法
// p = &b; // 不合法
```

这里不能重新给 p 赋予别的地址，但可以通过 p 修改 a。

### 6.4 双重 const
```c
uint8_t a = 10;

const uint8_t *const p = &a;

// p = ...;  // 不合法
// *p = 20;  // 不合法
```

### 6.5 const 的工程意义
在驱动函数中：

```c
int driver_send(const uint8_t *data,
                size_t length);
```

表示函数通过 data 读取数据，不允许通过该指针修改数据。

而：

```c
int driver_receive(uint8_t *data,
                   size_t capacity);
```

表示函数可以将数据写入调用者的缓冲区。

需要注意：

+ const 不等于物理内存写保护。
+ const 不保证多任务线程安全。
+ const 不阻止其他合法的非 const 引用修改原本可修改的对象。
+ 不允许通过强制转换修改原本定义为 const 的对象，否则属于未定义行为。

## 七、指针生命周期与内存安全
### 7.1 指针变量的生命周期不等于所指对象的生命周期
下面的函数存在严重错误：

```c
uint8_t *get_data(void)
{
    uint8_t temp[3] = {1, 2, 3};

    return temp;
}
```

`return temp` 返回的是指向数组首元素的地址值，不是把三个数组元素复制给调用者。

函数返回时，局部数组 temp 的生命周期结束。

调用者不能安全地通过返回的指针访问原数组。

**函数返回局部变量地址，是嵌入式开发中常见的悬空指针错误。**

### 7.2 返回值与返回地址的区别
返回普通值：

```c
uint8_t get_value(void)
{
    uint8_t a = 100;
    return a;
}
```

调用者获得数值 100，不依赖局部变量 a 继续存在。

返回局部地址：

```c
uint8_t *get_value(void)
{
    uint8_t a = 100;
    return &a;
}
```

返回的地址不能用于访问已经结束生命周期的对象。

两者的区别：

**返回值复制数据，返回指针复制地址；复制地址不会延长所指对象的生命周期。**

### 7.3 static 缓冲区
```c
uint8_t *get_data(void)
{
    static uint8_t buf[3] = {1, 2, 3};

    return buf;
}
```

static 局部数组具有静态存储期，在程序运行期间持续存在。

因此函数返回后，仍然可以在有效访问条件下通过该指针读取数据。

但是：

+ 多次调用共享同一个 buf。
+ 后续调用可能覆盖之前的数据。
+ 多任务使用时可能发生数据竞争。
+ static 不等于线程安全。

### 7.4 memcpy 复制数据
```c
#include <string.h>
#include <stdint.h>

void get_data(uint8_t *out)
{
    uint8_t temp[3] = {1, 2, 3};

    memcpy(out, temp, sizeof(temp));
}
```

调用：

```c
uint8_t data[3] = {0};

get_data(data);
```

执行之后：

```latex
data = {1, 2, 3}
```

因为复制操作在 temp 生命周期结束之前已经完成。

即使 temp 后续失效，也不影响调用者数组中已经复制的数据。

需要保证：

+ 目标缓冲区足够大。
+ 源缓冲区和目标缓冲区有效。
+ memcpy 的长度单位为字节。
+ 源和目标内存区域不能重叠；有重叠时应使用 memmove。

### 7.5 常见指针问题
| 问题 | 典型错误 |
| --- | --- |
| 空指针 | 对 NULL 解引用 |
| 野指针 | 使用未初始化的指针 |
| 悬空指针 | 访问生命周期已结束的对象 |
| 数组越界 | 通过指针访问有效范围之外的数据 |
| 类型不匹配 | 错误转换指针并按不兼容类型访问 |
| 对齐错误 | 按不满足对齐要求的类型访问内存 |
| 数据竞争 | 多个任务缺少同步地读写共享数据 |


注意：判断指针是否非 NULL 只能排除空指针，不能证明指针一定有效。

## 八、嵌入式实际应用
### 8.1 UART 发送与接收
ESP-IDF v5.5 系列 UART 驱动接口：

```c
int uart_write_bytes(
    uart_port_t uart_num,
    const void *src,
    size_t size
);
```

```c
int uart_read_bytes(
    uart_port_t uart_num,
    void *buf,
    uint32_t length,
    TickType_t ticks_to_wait
);
```

发送接口使用 `const void *`：

+ 数据源由调用者提供。
+ 驱动读取数据。
+ 不应通过这个参数修改发送数据。

接收接口使用 `void *`：

+ 调用者提供接收缓冲区。
+ 驱动将接收到的数据写入缓冲区。
+ 返回实际读取的字节数量或错误值。

发送示例（假设 UART 已完成初始化）：

```c
uint8_t tx_buf[] = {
    0xAA, 0x55, 0x01, 0x02
};

int written = uart_write_bytes(
    UART_NUM_1,
    tx_buf,
    sizeof(tx_buf)
);
```

对于数组 `tx_buf`，`sizeof(tx_buf)` 表示整个数组的字节长度。

如果把它换成指针变量，就不能再用 `sizeof(指针)` 计算完整缓冲区长度。

### 8.2 传感器驱动接口设计
假设需要读取 6 字节传感器原始数据。

推荐调用者提供缓冲区：

```c
#include <stdint.h>
#include <stddef.h>
#include <string.h>

#define SENSOR_DATA_SIZE 6U

// 由具体传感器驱动实现
// 成功返回 0，失败返回非 0
int sensor_read_raw(uint8_t *buf, size_t len);

int sensor_get_data(uint8_t *out,
                    size_t capacity)
{
    if (out == NULL ||
        capacity < SENSOR_DATA_SIZE) {
        return -1;
    }

    uint8_t temp[SENSOR_DATA_SIZE] = {0};

    if (sensor_read_raw(temp, sizeof(temp)) != 0) {
        return -2;
    }

    memcpy(out, temp, sizeof(temp));

    return 0;
}
```

调用者：

```c
uint8_t sensor_data[6] = {0};

int ret = sensor_get_data(
    sensor_data,
    sizeof(sensor_data)
);

if (ret == 0) {
    // sensor_data 保存读取结果
}
```

该设计的特点：

1. 由调用者管理数据生命周期。
2. 明确缓冲区容量。
3. 避免返回局部数组地址。
4. 通过临时缓冲区防止底层读取失败时直接覆盖调用者数据。
5. 适合读取固定长度、小数据量的传感器。

示例中的 `sensor_read_raw` 是需要根据具体芯片实现的函数，不是 ESP-IDF 内置接口。

### 8.3 通过二级指针返回驱动内部数据
```c
#include <stdint.h>
#include <stddef.h>

static uint8_t rx_buf[4] = {
    0xAA, 0x55, 0x01, 0x02
};

int get_rx_buffer(const uint8_t **out,
                  size_t *length)
{
    if (out == NULL || length == NULL) {
        return -1;
    }

    *out = rx_buf;
    *length = sizeof(rx_buf);

    return 0;
}
```

调用：

```c
const uint8_t *data = NULL;
size_t length = 0;

int ret = get_rx_buffer(&data, &length);
```

这里：

+ `const uint8_t **out` 用于返回只读数据指针。
+ `size_t *length` 用于返回数据长度。
+ 返回值用于表示操作状态。

不过，调用者只是获得了数据访问地址，不代表获得了缓冲区所有权。

对于共享缓冲区，必须进一步明确何时可以读取、何时会被覆盖，以及是否需要加锁。

### 8.4 DMA、FreeRTOS 中的使用注意事项
当 DMA 或其他任务需要访问某块缓冲区时，应重点检查：

+ 缓冲区是否在整个传输期间持续有效。
+ DMA 控制器是否能够访问该内存区域。
+ 是否存在缓存一致性要求。
+ 是否满足硬件地址和对齐限制。
+ 是否有其他任务同时写入。
+ 缓冲区数据何时可以重新使用。

不能把生命周期即将结束的局部数组地址交给仍在执行的异步 DMA 操作。

也不能仅因为一个共享数据指针具有 const 限定，就认定它在多个任务中一定安全。

## 九、常见错误与易混淆点
### 9.1 混淆指针大小和元素大小
错误理解：

```latex
uint16_t *p 是 4 字节指针，所以 p++ 加 4
```

正确理解：

在常见 32 位 MCU 中：

```latex
sizeof(p)  = 4
sizeof(*p) = 2
```

因此，对 uint16_t 数组中的有效元素指针执行 `p++`，前进 2 字节。

### 9.2 混淆十六进制与十进制地址
```latex
0x20000000 + 6 字节
= 0x20000006
```

不要把地址中的十六进制数字直接当作十进制数字计算。

### 9.3 认为函数返回后指针会恢复原来的指向
错误理解：

```latex
函数中的 p 被修改
函数退出后 p 自动变回原来的指向
```

正确理解：

函数形参 p 是独立变量，函数返回后其生命周期结束。

调用者的原始指针变量如果没有被直接或间接修改，就一直保持原来的地址值。

### 9.4 认为返回局部数组地址就等于返回数组数据
错误代码：

```c
uint8_t *get_data(void)
{
    uint8_t data[6] = {0};
    return data;
}
```

正确认识：

返回的是地址值，而不是数组内容。

函数返回后局部数组生命周期结束，不能通过该返回指针访问原数组。

### 9.5 认为 static 缓冲区一定安全
static 保证对象生命周期，但不保证：

+ 独立缓冲区。
+ 多任务访问安全。
+ 不会被覆盖。
+ 数据始终保持不变。

### 9.6 认为 const 就是完全只读
`const uint8_t *p` 只限制通过 p 修改所指对象。

如果原对象本身并非 const，其他合法访问路径仍然可以修改它。

## 十一、本章核心总结
本章最重要的八条结论：

1. 指针本身是变量，保存地址信息。
2. 指针类型决定解引用的对象类型及指针运算步长。
3. 数组不是指针，但数组表达式在多数情况下会转换为首元素指针。
4. 数组作为函数形参时会调整为指针类型，不能自动保留数组长度。
5. C 语言函数参数采用值传递，指针形参也是独立变量。
6. 二级指针可以让函数间接修改调用者的一级指针变量。
7. 返回指针仅传递地址，不会延长所指对象的生命周期。
8. 在嵌入式工程中，必须同时考虑指针类型、长度、生命周期、所有权与并发安全。

**学习重点：从“会使用指针”，提升到“能够正确分析内存访问、设计驱动接口并避免指针相关故障”。**
