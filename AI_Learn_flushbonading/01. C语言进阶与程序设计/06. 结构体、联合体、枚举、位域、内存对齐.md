## 二、必须掌握的知识重点

| 核心知识 | 必须理解的规则与工程意义 |
|---|---|
| **结构体** | 结构体按值赋值复制成员值；指针成员只复制地址，不克隆其所指内存。 |
| **内存对齐** | 成员偏移由目标 ABI 的对齐规则决定；尾部填充使结构体数组元素地址继续满足对齐。 |
| **联合体** | 共享相同存储，sizeof 由最大成员大小和对齐决定；不同成员重解释存在表示与可移植性问题。 |
| **枚举** | 枚举常量在 C11 中具有 int 类型，枚举对象类型的实际大小由实现选择，不应用 sizeof(enum) 当作外部协议字段宽度。 |
| **位域** | 声明位宽约束取值，布局顺序、分配单元等由实现决定；硬件寄存器和线缆协议优先用掩码与移位。 |

## 三、系统知识讲解与代码分析

### 一、核心概念
嵌入式程序需要同时处理两种数据组织方式。一种是供 C 代码使用的对象，例如一次采样结果、设备配置或任务消息。另一种是外部规定的字节格式，例如 UART 帧、传感器寄存器数据和 Flash 存储记录。

设计时，先确定对象需要表达什么，再确定这些内容在内存中怎样布局。如果数据要发给另一个设备，还要单独确定每个字段在协议中的宽度、顺序和字节序。

| 机制 | 作用 | 常见场景 |
| --- | --- | --- |
| `struct` | 将同时存在的字段组合成一个对象 | 采样结果、驱动配置、设备状态 |
| `union` | 让互斥的多种载荷共用存储 | 一条消息携带电压或脉冲计数 |
| `enum` | 给一组整数值命名 | 工作模式、状态机、错误码 |
| 位域 | 限制整型成员的位宽 | 工具链和布局已确定的内部状态 |
| 对齐与填充 | 满足类型的地址要求 | 分析成员偏移、数组步长与 RAM 占用 |

### 二、结构体
#### 2.1 类型、对象与成员访问
```c
#include <stdint.h>

typedef struct {
    uint32_t timestamp_ms;
    int16_t temperature_x100;
    uint16_t battery_mv;
} SensorSample;
```

`SensorSample` 是类型名。定义类型之后，可以声明一个对象并用成员名指定初值：

```c
SensorSample sample = {
    .timestamp_ms = 1000,
    .temperature_x100 = 2536,
    .battery_mv = 3700
};

SensorSample *p = &sample;
p->battery_mv = 3650;
```

`sample.battery_mv` 直接访问成员，`p->battery_mv` 通过指针访问同一个成员，等价于 `(*p).battery_mv`。执行赋值后，`sample.battery_mv` 为 `3650`。

使用初始化列表时，省略的整数成员初始化为零。例如 `SensorSample sample = { .battery_mv = 3700 };` 的其他两个成员为零。如果在函数内只写 `SensorSample sample;`，这个自动对象没有初始化，读取成员前应先赋值。

#### 2.2 内嵌成员与指针成员
结构体成员可以是整数、数组、指针，也可以是另一个结构体。内嵌结构体或数组的存储属于外层对象。指针成员自身属于外层对象，它指向的缓冲区另有自己的生命周期。

```c
#include <stdint.h>

typedef struct {
    uint8_t header[2];
    uint8_t *payload;
} Packet;

void copy_example(void)
{
    uint8_t raw[] = {10, 20};
    Packet a = { .header = {0xA5, 0x01}, .payload = raw };
    Packet b = a;

    b.header[0] = 0x5A;
    b.payload[0] = 99;

    /* a.header[0] 仍为 0xA5 */
    /* a.payload[0] 与 b.payload[0] 都读到 99 */
}
```

`Packet b = a;` 为 `b` 初始化一份独立的结构体值。复制 `header` 时，数组元素进入 `b` 自己的存储。复制 `payload` 时，复制的是地址值，所以两个成员仍指向 `raw`。修改 `raw[0]` 后，两个指针保存的地址都保持原值。

如果 `raw` 来自 `malloc()`，必须明确哪个对象负责释放。两个结构体副本持有同一个地址，不能各自释放一次。

#### 2.3 传参、返回值与生命周期
| 接口形式 | 适合的用途 | 调用后对原对象的影响 |
| --- | --- | --- |
| `void f(SensorSample s)` | 函数处理自己的结构体副本 | 修改普通成员不会影响原对象 |
| `void f(SensorSample *s)` | 函数更新调用者提供的对象 | 可通过 `s->member` 修改原对象 |
| `void f(const SensorSample *s)` | 函数借用对象进行读取 | 不能通过此指针直接修改结构体成员 |
| `SensorSample f(void)` | 函数构造一个结果并按值返回 | 调用者取得返回的结构体值 |


C 的参数按值传递。传入 `&sample` 时，复制的是地址值，函数可以沿这个地址访问调用者的对象。结构体按值传递的具体实现可能使用寄存器或内存，由 ABI 和编译器决定。

```c
SensorSample make_sample(uint32_t now_ms, uint16_t battery_mv)
{
    SensorSample result = {
        .timestamp_ms = now_ms,
        .battery_mv = battery_mv
    };

    return result;
}
```

`return result;` 返回结构体值。若改成返回 `&result`，调用结束后地址指向的自动对象已经结束生命周期。若结构体本身含有指针，按值返回也不会延长该指针所指对象的生命周期。

`const SensorSample *` 表达这个接口的访问权限。多任务同时访问同一个对象时，仍需要同步。结构体赋值可能包含多次读写，不能用来保证读取到一致的采样快照。

### 三、内存对齐与填充
#### 3.1 对齐要求、大小和偏移
以字节编址的 MCU 为例，4 字节对齐表示对象起始地址是 4 的倍数。地址 `0x20000004` 满足要求，`0x20000006` 不满足。某个成员是否需要 4 字节对齐，要看它自己的类型和目标 ABI。

| 工具 | 查询内容 | 例子 |
| --- | --- | --- |
| `sizeof` | 对象占用的字节数，包含填充 | `sizeof(SensorSample)` |
| `_Alignof` | 类型对起始地址的对齐要求 | `_Alignof(SensorSample)` |
| `offsetof` | 普通成员距对象开头的字节数 | `offsetof(SensorSample, battery_mv)` |


`_Alignof` 是 C11 运算符，结果类型为 `size_t`。合法对齐值是 2 的非负整数次幂，例如 1、2、4、8。目标实现决定支持哪些值。`offsetof` 由 `<stddef.h>` 提供。

#### 3.2 怎样手算布局
下面采用一组明确的练习前提：`uint8_t`、`uint16_t`、`uint32_t` 的大小和对齐分别为 1、2、4 字节。结构体按成员的最大对齐要求对齐，没有打包或额外对齐设置。

```c
#include <stdint.h>

typedef struct {
    uint8_t  channel;
    uint32_t timestamp_ms;
    uint16_t sample;
} AdcRecord;
```

1. `channel` 从偏移 0 开始，占 1 字节。
2. 下一个可用偏移是 1。`timestamp_ms` 要求 4 字节对齐，因此放在偏移 4，中间填充 3 字节。
3. `timestamp_ms` 占用偏移 4～7。`sample` 放在偏移 8，满足 2 字节对齐，占用 8～9。
4. 成员结束后已有 10 字节。结构体按 4 字节对齐，将大小补到 12 字节。

| 偏移 | 内容 |
| --- | --- |
| 0 | `channel` |
| 1～3 | 成员间填充 |
| 4～7 | `timestamp_ms` |
| 8～9 | `sample` |
| 10～11 | 尾部填充 |


数组中，相邻 `AdcRecord` 元素相隔 `sizeof(AdcRecord)`，即 12 字节。尾部填充让下一个元素仍从 4 的倍数地址开始。

如果在末尾增加 `uint16_t reference`，它可以从偏移 10 开始。原来的两个尾部填充字节变成成员存储，总大小仍是 12 字节。如果将原有三个成员改为 `timestamp_ms`、`sample`、`channel`，大小可降到 8 字节，整体对齐仍为 4。

#### 3.3 怎样验证实际目标
```c
#include <stddef.h>
#include <stdio.h>

void print_adc_record_layout(void)
{
    printf("size=%zu align=%zu timestamp_offset=%zu\n",
           sizeof(AdcRecord),
           _Alignof(AdcRecord),
           offsetof(AdcRecord, timestamp_ms));
}
```

将它放在 `AdcRecord` 定义之后，在 ESP32-S3 的 `app_main()` 中调用，或在已配置日志输出的 STM32 工程中运行。需要约束固定 ABI 时，可以用 `_Static_assert` 检查大小与偏移。

含有嵌套对象时，先算内层 `sizeof` 和对齐，再把内层当作一个完整成员放进外层。内层自带的填充占用它自己的空间，外层另外计算成员间和末尾的填充。

### 四、联合体
#### 4.1 共享存储与固定大小
```c
#include <stdint.h>

typedef union {
    uint32_t count;
    uint8_t raw[5];
} Payload;
```

`count` 和 `raw` 从同一个位置开始。按上一节的布局前提，最大成员 `raw` 要求 5 字节，`count` 带来 4 字节对齐要求，因此 `Payload` 占 8 字节。

写入 `count` 或 `raw` 时，`sizeof(Payload)` 都是 8。当前写入哪个成员只影响共享存储中的数据。需要同时保存两份有效数据时，使用结构体中的两个独立成员。

#### 4.2 数值转换与对象表示
```c
uint32_t count = 25;
float result = (float)count;
```

这是数值转换，结果为 `25.0f`。如果将整数 `25` 写进一个同时含有整数和浮点成员的联合体，再读浮点成员，读到的是按浮点规则解释的对象表示。

例如，在相应的 32 位整数与 IEEE 754 单精度表示下，整数 `25` 的位表示为 `0x00000019`，浮点数 `25.0f` 的位表示为 `0x41C80000`。位宽相同，表示规则不同。协议解析时，应依据协议的字节序明确拼接数据。

#### 4.3 用类型标记选择载荷
```c
#include <stdint.h>

typedef enum {
    DATA_VOLTAGE = 1,
    DATA_PULSE_COUNT = 2
} DataKind;

typedef struct {
    DataKind kind;
    union {
        uint16_t voltage_mv;
        uint32_t pulse_count;
    } value;
} Measurement;

Measurement make_pulse_count(uint32_t count)
{
    return (Measurement){
        .kind = DATA_PULSE_COUNT,
        .value = { .pulse_count = count }
    };
}
```

构造函数同时设置标记和载荷。接收方根据 `kind` 选择成员。C 不会替程序检查这两项是否一致，所以接口应尽量把它们作为一个整体构造和发布。

### 五、枚举
#### 5.1 值怎样确定
```c
typedef enum {
    LINK_IDLE = 0,
    LINK_CONNECTING = 4,
    LINK_CONNECTED,
    LINK_ERROR = -1
} LinkState;
```

第一个常量没有显式赋值时取 0。其后的常量若省略赋值，就取前一个值加 1。因此 `LINK_CONNECTED` 为 5。如果在 `LINK_ERROR` 后面添加未显式赋值的 `LINK_RETRY`，它会取 0，与 `LINK_IDLE` 重复。

C 允许枚举常量同值。如果两种状态需要分别处理，就应分配不同的值。

#### 5.2 枚举对象为什么可能是 4 字节
按 C11，`LINK_CONNECTED` 这种枚举常量具有 `int` 类型。`LinkState state;` 中的 `state` 是枚举对象，其兼容整数类型由实现选择，须能表示所有列出的枚举值。

| 表达式 | 查询对象 |
| --- | --- |
| `sizeof(LINK_CONNECTED)` | 枚举常量表达式的类型大小，C11 下为 `sizeof(int)` |
| `sizeof(LinkState)` | 目标实现为该枚举类型选择的对象大小 |
| `_Alignof(LinkState)` | 目标实现为该枚举类型选择的对齐要求 |


许多 GCC 目标配置下会得到 4 字节。目标 ABI 和 `-fshort-enums` 等选项可以影响结果。若题目只给出一个枚举定义，不能仅凭常量个数推导其对象大小。

#### 5.3 外部输入必须校验
`(LinkState)raw` 执行类型转换，不检查 `raw` 是否符合业务约定。从 UART 收到一个状态字节后，应按协议列出的值校验，再映射为内部状态。即使内部 `LinkState` 占 4 字节，协议状态字段也可以明确规定只占 1 字节。

### 六、位域
#### 6.1 位宽约束成员值
```c
typedef struct {
    unsigned int ready : 1;
    unsigned int error : 1;
    unsigned int mode  : 2;
} DeviceFlags;
```

`ready`、`error` 各可表示 0～1，`mode` 可表示 0～3。无符号 N 位字段的最大值为 `2^N - 1`。输入应先检查，再赋给位域，否则超出范围的值可能变成另一个有效位模式，例如将 `4` 写入这里的无符号 `mode` 后得到 `0`。

#### 6.2 位域的布局与访问
相邻位域可以共用存储单元。位宽总和为 4 位，仍无法仅凭声明得出整个结构体占用多少字节。分配顺序、是否跨存储单元以及结构体布局受编译器与目标 ABI 影响。

可以对整个 `DeviceFlags` 求 `sizeof`，不能对 `flags.mode` 直接求 `sizeof` 或取地址。写入一个位域也可能要读取、修改并写回存储单元。任务与 ISR 分别写两个相邻字段时，仍需要考虑同步。

对于硬件寄存器，应按芯片手册和厂商头文件规定访问，尤其要检查访问宽度和写入副作用。对于外部协议，应使用掩码和移位明确指定每一位。

### 七、嵌入式工程应用
#### 7.1 将流量采样对象编码为 UART 字节
假设 MCU 需要上传一条流量采样。内部用 `FlowSample` 保存记录。这里自定义一个 7 字节的数据格式：

| 偏移 | 字段 | 规则 |
| --- | --- | --- |
| 0 | 状态 | bit 0 为 ready，bit 1 为 error，bit 2～3 为 mode |
| 1～4 | 序号 | 32 位，高字节在前 |
| 5～6 | 流量 | 16 位，单位 mL/s，高字节在前 |


```c
#include <stddef.h>
#include <stdint.h>

enum { FLOW_FRAME_SIZE = 7 };

typedef struct {
    uint32_t sequence;
    uint16_t flow_ml_s;
    uint8_t ready;
    uint8_t error;
    uint8_t mode;
} FlowSample;

int encode_flow_sample(const FlowSample *sample,
                       uint8_t *out,
                       size_t capacity)
{
    if (sample == NULL || out == NULL || capacity < FLOW_FRAME_SIZE) {
        return -1;
    }

    if (sample->ready > 1u || sample->error > 1u || sample->mode > 3u) {
        return -2;
    }

    out[0] = (uint8_t)(sample->ready
                    | (sample->error << 1)
                    | (sample->mode << 2));

    out[1] = (uint8_t)(sample->sequence >> 24);
    out[2] = (uint8_t)(sample->sequence >> 16);
    out[3] = (uint8_t)(sample->sequence >> 8);
    out[4] = (uint8_t)sample->sequence;

    out[5] = (uint8_t)(sample->flow_ml_s >> 8);
    out[6] = (uint8_t)sample->flow_ml_s;

    return 0;
}
```

例如 `ready=1`、`error=0`、`mode=3` 时，状态为 `0x01 | 0x00 | 0x0C = 0x0D`。若序号为 `0x00000102`、流量为 `0x0136`，输出如下：

```text
0D 00 00 01 02 01 36
```

序号虽小，也要写满 4 字节。开头的 `00` 是协议字段的一部分。发送长度使用 `FLOW_FRAME_SIZE`，内部对象的 `sizeof` 用于管理本地存储。

#### 7.2 STM32 DMA 和 ESP32-S3 任务通信
在 STM32 上，若采用 DMA 从调用者的发送缓冲区取数，从启动到驱动交还缓冲区期间，缓冲区必须保持有效且内容不被覆盖。可以由发送任务独占一个长期缓冲区，收到完成事件后再编码下一帧。DMA 读完源缓冲区和 UART 发完最后一位可能是两个时刻，按具体驱动的完成约定操作。

在 ESP32-S3 的 FreeRTOS 工程中，可以让采集任务通过队列按值发送 `FlowSample`，由通信任务取出后编码。队列项如果改成指针，队列只复制地址，此时还需要规定缓冲区何时可以回收或复用。


## 四、工程应用与常见陷阱

1. DMA 在传输完成前不能复用源缓冲区，static 只保证地址寿命不保证内容不被改写。
2. 通信协议应显式编码字段宽度和大小端，不直接 memcpy 整个结构体当成跨平台协议帧。
3. 在有多任务或 ISR 修改结构体的情况下，结构体赋值不天然是原子快照。

## 五、个人易错点与复盘

### 八、常见错误与个人回顾
| 容易混淆的点 | 检查方法 |
| --- | --- |
| 结构体赋值与指针赋值 | 先看左侧对象类型。结构体复制成员值，指针复制地址值。 |
| 指针地址与所指内容 | `b.ptr[0] = 8` 修改目标对象。要改 `b.ptr` 保存的地址，须对 `b.ptr` 本身赋值。 |
| `sizeof` 与 `_Alignof` | 分别问“对象占多少字节”和“起始地址须满足什么条件”。 |
| 嵌套填充的归属 | 先划出内层对象的整个范围，再区分内层填充与外层填充。 |
| 联合体大小和当前成员 | 查询的是整个类型的大小，使用较小成员也不会缩小对象。 |
| 枚举常量和枚举对象 | 分别用 `sizeof(枚举常量)` 和 `sizeof(枚举类型)` 检查。 |
| 位宽和协议位置 | 位域的冒号数字约束值宽。协议位置由掩码、移位和协议定义确定。 |
| UART 十六进制字节 | 先写偏移和字段宽度，再逐字段填入，最后核对总字节数。 |

## 七、参考答案与解析（完成自检后再看）

**1.** 偏移分别为 0、4、8，尾部补齐到 12；整体对齐 4。
