## 一、动态内存与生命周期
动态内存用于在运行时申请存储空间，常用接口声明在：

```c
#include <stdlib.h>
```

| 接口 | 功能 |
| --- | --- |
| malloc | 申请指定字节数的内存，内容未初始化 |
| calloc | 申请多个元素的空间，并将所有位清零 |
| realloc | 调整已有动态内存块的大小 |
| free | 释放动态申请的内存 |


在常见 MCU 工程中，这些接口通常从堆中分配内存，具体实现取决于 C 库及运行环境。

```c
void example(void)
{
    int *p = malloc(sizeof *p);
}
```

需要区分两个对象：

+ **指针变量 p**：具有自动存储期，通常位于栈或寄存器中，也可能被优化。
+ **申请到的内存块**：具有分配存储期，不会因为函数返回而自动释放。

如果函数返回前没有释放内存，也没有把地址交给其他有效指针保存，就会造成内存泄漏。

## 二、size_t 与申请大小
`size_t` 是用于表示对象大小的无符号整数类型，也是 `sizeof` 表达式结果的类型。

范围为：

```latex
0 ～ SIZE_MAX
```

位宽取决于目标平台。常见 32 位 MCU 工具链中的 `size_t` 为 32 位，但应以实际工具链为准。

```c
#include <stddef.h>
#include <stdint.h>
```

+ `<stddef.h>` 提供 `size_t`。
+ `<stdint.h>` 提供 `SIZE_MAX`。
+ 打印 `size_t` 使用 `%zu`。

```c
printf("%zu\n", sizeof(int));
```

**类型能表示的大小，不等于设备实际能申请到的内存大小。**

### 2.1 指针大小与元素大小
```c
uint16_t *p;
```

| 表达式 | 含义 |
| --- | --- |
| sizeof p | 指针自身的大小 |
| sizeof *p | 所指元素 uint16_t 的大小 |


在 `sizeof(uint16_t) == 2`、指针为 4 字节的平台上：

```c
sizeof p   // 4
sizeof *p  // 2
```

申请数组时推荐：

```c
uint16_t *p = malloc(count * sizeof *p);
```

这样修改 `p` 的类型后，不容易遗漏申请大小的修改。

这里 `sizeof *p` 不会实际解引用 `p`。

## 三、malloc：申请未初始化的内存
接口：

```c
void *malloc(size_t size);
```

+ 参数单位是字节。
+ 成功返回内存块地址。
+ 失败返回 `NULL`。
+ 内存未初始化，不能直接把其中内容当作有效值读取。

```c
int *p = malloc(sizeof *p);

if (p == NULL) {
    return;
}

*p = 100;
printf("%d\n", *p);

free(p);
p = NULL;
```

**必须在首次解引用之前检查申请结果。**

错误示例：

```c
int *p = malloc(sizeof *p);

*p = 100;  // 申请失败时已经发生非法访问

if (p == NULL) {
    return;
}
```

## 四、free：释放内存与指针置空
接口：

```c
void free(void *ptr);
```

释放后，该内存块对应对象的生命周期结束，不能继续通过旧指针访问它。

```c
free(p);
p = NULL;
```

这两行作用不同：

| 操作 | 作用 |
| --- | --- |
| free(p) | 释放所指向的动态内存 |
| p = NULL | 修改指针变量自身 |


**free 不会自动把指针设为 NULL，置空也不会自动释放内存。**

### 4.1 free(NULL) 合法
```c
free(NULL);
```

不执行任何释放操作。

### 4.2 不能随意释放地址
以下操作不合法：

```c
int value;
free(&value);  // 自动变量不是动态申请的对象
```

```c
int *p = malloc(4 * sizeof *p);

if (p != NULL) {
    free(p + 1);  // 不是分配函数返回的起始指针
}
```

```c
free(p);
free(p);  // 重复释放
```

应释放分配函数返回的有效指针，且同一块有效分配只释放一次。

## 五、别名、悬垂指针与重复释放
### 5.1 复制指针不会复制内存
```c
int *p = malloc(sizeof *p);
if (p == NULL) {
    return;
}

int *q = p;
*p = 10;
```

只有一块动态内存，`p`、`q` 都指向它。

```c
q[0] = 20;
```

通过 `p` 读取也会得到 `20`。

### 5.2 释放后，其他别名不会自动置空
```c
free(p);
p = NULL;
```

`q` 不会联动变为 `NULL`，此时它是悬垂指针，不能继续使用：

```c
printf("%d\n", *q);  // 释放后使用：未定义行为
free(q);            // 重复释放：未定义行为
```

即使原来的字节暂时还在、某次运行看起来正常，也不能继续访问。

如果别名仍在作用域内，可以直接覆盖其旧值：

```c
q = NULL;
```

**指针非空，不代表所指对象仍有效。**

## 六、内存泄漏与提前返回
### 6.1 覆盖唯一指针
假设申请都成功：

```c
int *p = malloc(4 * sizeof *p);

p = malloc(8 * sizeof *p);

free(p);
p = NULL;
```

第二次赋值覆盖了第一块内存的地址。

第一块内存没有释放，也没有其他指针保存地址，因此泄漏。

最后的 `p = NULL` 无法找回它。

### 6.2 提前返回遗漏释放
```c
uint8_t *buf = malloc(len);
if (buf == NULL) {
    return -1;
}

if (len > 128) {
    return -2;  // 泄漏
}
```

可以返回前释放：

```c
if (len > 128) {
    free(buf);
    return -2;
}
```

但如果条件可以提前判断，更合理的是：

```c
if (len == 0 || len > 128) {
    return -2;
}

uint8_t *buf = malloc(len);
if (buf == NULL) {
    return -1;
}
```

原则：

**先校验参数，再申请资源；申请之后的每条退出路径都要明确释放责任。**

## 七、通过二级指针返回动态内存
C 函数参数按值传递。

下面的写法不能修改调用者的指针：

```c
void allocate(uint8_t *out)
{
    out = malloc(64);
}
```

```c
uint8_t *data = NULL;
allocate(data);

// data 仍为 NULL
```

如果申请成功，这个错误示例还会因为没有保存返回的地址而造成泄漏。

可以使用二级指针：

```c
#include <stdint.h>
#include <stdlib.h>
#include <string.h>

int prepare_buffer(uint8_t **out, size_t len)
{
    if (out == NULL) {
        return -1;
    }

    if (len == 0 || len > 128) {
        return -2;
    }

    uint8_t *buf = malloc(len);
    if (buf == NULL) {
        return -3;
    }

    memset(buf, 0, len);

    *out = buf;
    return 0;
}
```

调用：

```c
void test(void)
{
    uint8_t *data = NULL;

    int ret = prepare_buffer(&data, 64);

    if (ret == 0) {
        data[0] = 0x55;
    }

    free(data);
    data = NULL;
}
```

接口约定：

+ 调用时传入有效的输出参数地址。
+ 本例调用前 `data` 为 `NULL`。
+ 失败时不修改 `data`。
+ 成功后由调用者负责释放。
+ 不要用输出结果覆盖另一块尚未释放内存的唯一指针。

| 表达式 | 本例含义 |
| --- | --- |
| out | &data |
| *out | 调用者的指针变量 data |
| **out | data 指向的一个元素 |


函数返回时，局部指针 `buf` 生命周期结束。

但堆内存没有释放，地址已经保存到 `data` 中，因此仍可使用。

## 八、申请大小的乘法溢出
即使使用 `size_t`，乘法也可能发生无符号回绕。

假设 `size_t` 为 32 位，`sizeof(uint32_t) == 4`：

```c
size_t count = 0x40000001;
uint32_t *p = malloc(count * sizeof *p);
```

计算结果：

```latex
数学结果：0x40000001 × 4 = 0x100000004
32 位结果：0x00000004
```

最终只申请了 4 字节，却可能按大量元素使用，造成越界。

### 8.1 乘法前用除法检查
```c
#include <stdint.h>
#include <stdlib.h>

uint32_t *alloc_samples(size_t count)
{
    uint32_t *p;

    if (count == 0) {
        return NULL;
    }

    if (count > SIZE_MAX / sizeof *p) {
        return NULL;
    }

    p = malloc(count * sizeof *p);
    return p;
}
```

关键条件：

```c
count > SIZE_MAX / sizeof *p
```

**先检查，再乘法。**

不能等乘积已经回绕后再判断。

例如，每个元素占 4 字节时：

```latex
SIZE_MAX / 4 = 0x3FFFFFFF
```

如果：

```c
count = 0x40000000;
```

则必须拒绝这次申请，因为直接计算 `count * 4` 会回绕为 0。

## 九、数组边界与字符串空间
### 9.1 元素数与有效下标
```c
uint16_t *p = malloc(6 * sizeof *p);
```

申请成功后：

+ 有效元素为 `p[0]`～`p[5]`。
+ `p + 6` 可以形成尾后指针。
+ 不能通过 `p + 6` 解引用访问元素。

```c
p[5] = 100;       // 合法
*(p + 6) = 100;   // 越界
```

循环应写：

```c
for (size_t i = 0; i < count; i++) {
    p[i] = 0;
}
```

`i <= count` 会多访问一个元素。

例如，申请 10 个 `uint16_t`，却访问下标 `0～10`：

+ 实际访问 11 个元素。
+ 多访问 1 个元素。
+ 在 `sizeof(uint16_t) == 2` 的平台上，越界 2 字节。

### 9.2 字符串需要结束符空间
```c
const char *src = "STM32";
```

| 表达式 | 结果 |
| --- | --- |
| strlen(src) | 5，不包含 '\0' |
| sizeof "STM32" | 6，包含 '\0' |
| sizeof src | 指针自身大小 |


正确复制：

```c
char *p = malloc(strlen(src) + 1);
if (p == NULL) {
    return;
}

strcpy(p, src);

free(p);
p = NULL;
```

这里针对已知有效、长度正常的字符串。

通用接口还应根据输入来源检查长度及加一是否溢出。

### 9.3 复制字符与复制地址
```c
strcpy(p, src);  // 复制字符内容，包含 '\0'
char *q = p;    // 复制地址
```

示例：

```c
const char *src = "ABC";

char *p = malloc(strlen(src) + 1);
if (p == NULL) {
    return;
}

strcpy(p, src);

char *q = p;
q[1] = 'X';
```

结果：

| 指针 | 所指字符串 |
| --- | --- |
| src | "ABC" |
| p | "AXC" |
| q | 与 p 指向同一份 "AXC" |


`p` 中是独立副本，修改它不改变字符串字面量。

**字符串字面量本身不能修改。**

收尾只释放一次：

```c
free(p);
p = NULL;
q = NULL;
```

## 十、calloc：分配并按位清零
接口：

```c
void *calloc(size_t count, size_t size);
```

示例：

```c
uint16_t *p = calloc(6, sizeof *p);
if (p == NULL) {
    return;
}
```

假设 `sizeof(uint16_t) == 2`：

+ 申请的数据空间为 `6 × 2 = 12` 字节。
+ 六个元素的初始值均为 `0`。
+ 有效下标仍为 `0～5`。
+ 使用结束后仍需 `free(p)`。

与 `malloc` 对比：

| 写法 | 初始内容 |
| --- | --- |
| malloc(6 * sizeof *p) | 未初始化 |
| calloc(6, sizeof *p) | 所有位清零 |


注意：

+ 按位清零不等于对所有类型都完成语义初始化。
+ C 不普遍保证浮点零、空指针都使用全零位表示。
+ 扩容时，`realloc` 不会因为原块来自 `calloc` 而自动清零新增部分。

## 十一、realloc：调整内存大小
接口：

```c
void *realloc(void *ptr, size_t new_size);
```

本节统一讨论 `new_size > 0`，避免依赖零大小调用在不同标准、实现中的差异。

| 情况 | 结果 |
| --- | --- |
| 成功 | 返回调整后的指针，可能原地调整，也可能搬家 |
| 失败 | 返回 NULL，原内存仍有效 |
| 扩大成功 | 原有内容保留，新增部分未初始化 |
| 缩小成功 | 保留新大小范围内的原有内容 |


### 11.1 使用临时指针
错误风险：

```c
p = realloc(p, new_size);
```

失败时会覆盖 `p`。

如果没有其他有效引用，原块泄漏。

正确写法：

```c
uint16_t *tmp = realloc(p, 10 * sizeof *p);

if (tmp == NULL) {
    // p 仍有效，调用者决定继续使用还是释放
} else {
    p = tmp;
}
```

成功后：

+ 后续使用返回的新指针。
+ 旧指针及旧别名停止使用，即使地址看起来相同。
+ 不需要额外释放旧块。
+ 最终释放当前有效指针一次。

### 11.2 完整例程
```c
int resize_example(void)
{
    uint16_t *p = calloc(6, sizeof *p);
    if (p == NULL) {
        return -1;
    }

    p[0] = 100;

    uint16_t *tmp = realloc(p, 10 * sizeof *p);
    if (tmp == NULL) {
        free(p);
        return -2;
    }

    p = tmp;

    for (size_t i = 6; i < 10; i++) {
        p[i] = 0;
    }

    // 使用 p[0]～p[9]

    free(p);
    p = NULL;

    return 0;
}
```

### 11.3 字符串扩容例程
```c
#include <stdlib.h>
#include <string.h>

int string_example(void)
{
    const char *src = "STM32";

    char *p = malloc(strlen(src) + 1);
    if (p == NULL) {
        return -1;
    }

    strcpy(p, src);

    char *tmp = realloc(p, 32);
    if (tmp == NULL) {
        free(p);
        return -2;
    }

    p = tmp;
    p[0] = 's';

    // 此时字符串为 "sTM32"
    // 原有的 '\0' 已保留，不需要再次补写

    free(p);
    p = NULL;

    return 0;
}
```

## 十二、内存碎片与嵌入式使用取舍
### 12.1 外部碎片
假设堆布局如下，忽略管理开销：

| 块 | 大小 | 状态 |
| --- | :--- | --- |
| A | 32 字节 | 空闲 |
| B | 32 字节 | 使用中 |
| C | 32 字节 | 空闲 |
| D | 32 字节 | 使用中 |


总空闲空间为 64 字节，但最大连续空闲块只有 32 字节，因此申请 48 字节可能失败。

如果释放 B，且分配器支持合并相邻空闲块，A、B、C 可合并为 96 字节。

| 问题 | 本质 |
| --- | --- |
| 内存泄漏 | 内存仍被分配，但丢失了正常释放所需的引用 |
| 外部碎片 | 空闲内存分散，无法满足较大的连续申请 |
| 内存越界 | 访问了分配范围之外的内存 |


### 12.2 常见工程选择
| 场景 | 常见方案 |
| --- | --- |
| 固定大小、长期使用的 UART 缓冲区 | 静态数组，或初始化阶段申请一次 |
| 高频申请、释放同规格数据块 | 固定大小内存池 |
| 低频、长度变化的数据 | 根据需求使用动态内存 |
| 严格实时路径 | 评估分配器最坏耗时，优先考虑预分配 |
| ISR | 不默认普通分配接口可用，通常把分配工作交给任务 |


例如：

```c
static uint8_t rx_buf[256];
```

该数组具有静态存储期，不需要 `free()`。

使用长期缓冲区可以减少反复申请、释放的开销和时间波动，也能减少运行期间动态分配带来的碎片风险。

但静态分配并不自动解决 DMA、任务、ISR 同时访问的问题。

使用 RTOS 专用分配接口时，应采用其规定的释放方式，不要未经确认混用不同分配器。

## 十三、本章易错点
| 易错认识 | 正确规则 |
| --- | --- |
| uint16_t *p，所以 sizeof *p 是 4 | sizeof *p 是元素大小，本章题设为 2 |
| strlen(src) 得到指针大小 | 它得到字符串长度，不含结束符 |
| "STM32" 申请 5 字节即可 | 完整字符串需要 6 字节 |
| 指针非空就能访问 | 非空指针也可能悬垂或无效 |
| free(p) 会自动置空 | 必须自行赋 p = NULL |
| 给一个别名置空，其他别名也置空 | 各指针变量独立 |
| realloc 成功后旧别名仍能用 | 只使用返回的新指针 |
| 无符号乘法不会出问题 | 虽然回绕有定义，仍可能导致申请过小 |
| 程序正常运行说明没有越界 | 未定义行为可能暂时表现正常 |
| 负错误码可以用 uint8_t 返回 | 需要保留负值时使用合适的有符号类型 |


## 十四、代码检查顺序
编写动态内存代码时，依次确认：

1. **大小**：单位是否正确，字符串是否包含 `'\0'`，计算是否溢出。
2. **申请**：是否在首次访问前检查失败。
3. **使用**：下标是否在有效范围内，是否存在并发访问。
4. **所有权**：成功后由谁使用、谁释放。
5. **退出**：每条返回路径是否正确处理资源。
6. **释放后**：是否仍有旧指针或别名被继续使用。
